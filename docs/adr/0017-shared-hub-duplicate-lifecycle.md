# ADR-0017：严格重复工单共享 Hub 生命周期

- 日期：2026-10-13
- 状态：Accepted
- 范围：KSM/智齿/Zammad 等外部来源的新接入非拆单工单

## 背景

原 `hub_dedup` 在工单毕业后先创建新 Hub，命中重复时再把新 Hub 标记为
`superseded`。这会保留多条 Hub 记录，且没有统一定义多工单共享一个 Hub 后的撤销、
答复、退回、产研复发等状态收敛规则。

## 决策

### 1. 严格匹配与单 Hub

- 只对新接入的 `Raw` 工单自动查重；`Child` 拆单子单不进入该关联逻辑。
- 候选必须同产品线、同 Hub 类型，且符合生命周期资格。
- 标题和问题描述归一化后完全相同时可直接命中；语义匹配时，向量相似度和
  LLM 置信度都必须不低于 `0.95`。拿不准时不关联。
- 命中后直接把新工单绑定到原 Hub，删除仅用于匹配的临时 Hub，不再留下第二条
  `superseded` Hub。`occurrence_count` 按实际关联工单数重算。
- 主管人工毕业代表明确判断，保持不自动查重。

### 2. 状态和处理人继承

- 新工单关联后继承原 Hub/有效原工单的状态、处理环节、处理人和责任人。
- 处理共享 Hub 时，只对尚未终态、且未被客户撤销的关联工单扇出答复、补资料、
  处理人变更和产研发布通知。
- 已答复/已关闭但没有正式答复的历史 Hub 不允许自动关联。
- 当 Hub 的全部历史关联工单都处于“补充资料”或“退回转单”时，代表已经没有
  正常状态工单；新严格重复工单允许复用原 Hub，并把新工单和 Hub 重置为“处理中”。
  只要仍存在一张正常状态工单，就不进入该重激活分支。

KSM 边界：现有入库主链会在 AI 分类/严格查重前立即用初始分派人调用
`lockKsmOrder + handleKsmOrder`。严格命中后本地处理人会正确继承，但 KSM 当前没有已接入的
“只更换当前处理人”接口。本次不冒险重复调用 `handleKsmOrder`（会重复生成“已受理”动作），
也不把整个 KSM 接管延迟到 LLM 完成后（会影响正常受理时效）。因此外部 KSM 节点处理人同步
需要 KSM 提供明确的转派接口后另行接入；这不影响本地共享 Hub、状态、处理人和后续出站身份。

### 3. 客户撤销是工单级事件

- KSM `status=5` 只关闭当前来源工单，保存处理说明“客户主动撤销关闭工单”，并取消该工单
  待发送的出站动作。
- 共享 Hub 还有其他有效工单时，Hub 保持处理中；仅当所有关联工单都已终态时才关闭 Hub。
- 撤销说明不写入 Hub 公共答复，避免覆盖其他客户共享的处理说明。
- 如 Hub 因全部工单撤销而关闭，之后又收到严格匹配的新工单，允许重新激活原 Hub。

### 4. 历史结果的处理

- 历史关联工单全部为“退回转单”或“补充资料”时：新重复工单不继承旧终态，
  而是重新激活原 Hub；历史工单保持原状态，旧退回说明不得再次自动发送给新工单。
- 退回类 Hub 仍有其他正常状态历史工单时：保留既有生命周期，不触发上述重激活。
- 有正式答复的已答复/已关闭 Hub：新工单继承终态和处理说明，并向来源系统补发答复。
- 已完成的 `Bug_fix`/`Demand` 再次出现同一问题：复用原 Hub，在原处理说明后追加
  “客户反馈问题未解决退回”，把原 Linear 编号和状态存入 `linear_history`，然后创建新的
  Linear issue。旧周期已终态工单不回滚、不接收新周期回写。

## 安全与兼容性

- 无严格命中时继续走原创建 Hub、分配、审核、Linear 推送和 Operation 答复流程。
- embedding 或 LLM 不可用时降级为不关联，不影响新工单正常毕业。
- 所有关联写入 `ticket_hub_issue_history` 和 `agent_decisions`，便于追溯。
- `linear_history` 通过 Alembic 迁移新增，当前 Linear 字段的展示和同步契约保持不变。

## 验证

- 严格查重、共享 Hub、KSM 撤销、退回、答复、处理人、Linear 新周期和历史终态隔离专项用例通过。
- 排除与本改动无关的既有 AI 客服图片契约、Linear 评论回写用例后，后端回归为 `1584 passed, 6 deselected`。
- 本改动涉及文件的 Ruff 检查和 `git diff --check` 通过；Alembic 单一 head 为 `0060_hub_linear_history`。

## 被替代的方案

- 保留每张重复工单的 `superseded` Hub：拒绝，因为不符合 Hub 唯一性，且状态同步容易漂移。
- 客户撤销直接关闭 Hub：拒绝，因为会中断同一 Hub 下其他客户的正常处理。
- 已完成产研问题复发时创建新 Hub：拒绝，因为会割裂同一问题的历史；改为原 Hub 新建
  Linear 周期并保留历史。
